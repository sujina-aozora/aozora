## 4. Design & content recommendations

1. **Lead with the customer's problem, then the solution.** Every service block uses こんなときに → 対応内容 → 選ぶ理由.
2. **Qualitative cost message** (no figures): 日本とネパールの協働による効率的な開発 / 日本式の進行・品質管理 / 必要な分だけ使える柔軟な体制 / AIを活用した効率的な開発.
3. **Conditional commitments**: when an A-item is approved, show it with its scope next to it (e.g. 「営業時間内（平日9:00–18:00）」). Never as a site-wide badge.
4. **Group framing**: one point of contact, three roles. KH Plus = 課題整理・補助金; AOZORA Japan = 窓口・要件・設計・品質; Parijat = 開発・QA; AI = efficiency. Always labelled 「グループでの連携イメージ」, not an org chart.
5. **Mark interpretation** in the How We Work diagram: documented roles are solid; illustrative ones are shown as outline/dotted with a legend 「※連携のイメージです」.
6. **Case cards**: show documented fields now; problem and outcome slots appear only once data exists (no placeholders visible to judges).
7. **Visuals**: original SVG diagrams instead of stock or AI photos; text logotype until the official file arrives.
8. **Japanese first**: the Japanese site is complete before any English work. English pages mirror only approved Japanese content.
9. **Accessibility and portability**: AA contrast, keyboard-operable Finder and stepper, works when opened from `file://`.
